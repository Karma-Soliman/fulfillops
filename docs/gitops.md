# FulfillOps GitOps with Argo CD

## Architecture

Git is the desired-state record. Argo CD reads the public repository's `main` branch and applies
the kind Kustomize overlay to the `fulfillops` namespace. Changes reach the cluster through a
reviewed pull request and merge.

```mermaid
flowchart LR
    PR[Reviewed pull request] --> Main[GitHub main]
    Main -->|HTTPS, anonymous read| Argo[Argo CD]
    Argo -->|Kustomize overlay| Cluster[kind cluster]
    Cluster --> App[fulfillops namespace]
```

The Argo CD installation is pinned to v3.6.1 through the upstream release's official install
manifest URL in `infra/argocd/install/kustomization.yaml`. The release page's Quick Start gives
the command:

```text
kubectl apply -n argocd --server-side --force-conflicts -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.6.1/manifests/install.yaml
```

The namespace-scoped Argo CD installation is applied with server-side apply because its CRD
definitions are too large for client-side apply annotations.

## Repository access

The FulfillOps repository is public, so Argo CD fetches it anonymously over HTTPS. No repository
credential, deploy key, or repository Secret is configured.

If the repository becomes private, create a read-only deploy key scoped to this repository. A
local bootstrap script should read the private key from an ignored local file and create an Argo CD
repository Secret labelled `argocd.argoproj.io/secret-type: repository`, with `type: git`, the
repository URL, and `sshPrivateKey` from that file. The key must never enter Git, shell output, or
a committed manifest. A repository-specific, read-only key follows least privilege: it cannot
write code, grants access to only one repository, and can be revoked independently. That is safer
than a personal SSH key or token, which can grant broader access and is tied to a person's account.

## AppProject limits

`infra/argocd/project.yaml` allows only the FulfillOps repository, only the `fulfillops` namespace
on this cluster, and only the cluster-scoped `Namespace` kind. The source restriction prevents
loading another repository; the destination restriction prevents writes to other namespaces or
clusters; the resource allowlist prevents this application from creating other cluster-wide
resources.

## Sync ordering and durable data

Argo CD uses the sync waves already present on the Kubernetes resources:

1. PostgreSQL StatefulSet, wave `0`.
2. Migration Job, `Sync` hook at wave `1`; `BeforeHookCreation` removes a previous immutable Job
   before creating the next one.
3. API and worker Deployments, wave `2`.

The PostgreSQL StatefulSet is marked `argocd.argoproj.io/sync-options: Prune=false`. This prevents
automated pruning from deleting the database StatefulSet. Its PVC is generated by the StatefulSet
and is not a standalone Kustomize resource; retaining the StatefulSet also avoids an accidental
database teardown during ordinary source changes. Treat database and PVC removal as a deliberate
operator action.

The `fulfillops-db` Secret is not in Git. `scripts/bootstrap-secrets.sh` creates it locally, so
Argo CD neither creates nor prunes it.

## Where automated self-heal is safe

Self-heal is appropriate for reversible stateless state such as replica counts, application
configuration, and Services. It restores the values that passed review in Git.

Human approval is required before database or PVC deletion, destructive pruning, schema migration,
or any other irreversible action. Self-heal does not make destructive changes safe; review the Git
diff and its impact before merging those changes.

## Release and recovery

Build and load the desired image, update the image tag in
`infra/k8s/overlays/kind/kustomization.yaml`, then send that change through a pull request. After
merge to `main`, Argo CD reconciles the new revision. Use `make argocd-refresh` to request an
immediate hard refresh instead of waiting for its normal polling interval.

For an image SHA, run `./scripts/release.sh --image <full-commit-sha>`, or through Make as
`make release ARGS="--image <full-commit-sha>"`. The script refuses to build unless that SHA is
exactly the current `HEAD`, and checks its timestamped release branch before building. For a
release note, use `./scripts/release.sh --note "text"` or
`make release ARGS='--note "text"'`. Arguments belong after `ARGS=` because Make parses its own
options before it runs the target.

`kubectl rollout undo`, `argocd app rollback`, or a manual patch is not the final fix: automated
self-heal can revert a live-only change, and Git would still describe the previous state. Make the
corrective change through a reviewed Git commit so Git and the cluster converge on the same desired
state.

## Commands

- `make argocd-install` installs the pinned Argo CD release and waits for its workloads.
- `make argocd-bootstrap` applies the initial project and Application after this branch's PR is
  merged to `main`.
- `make argocd-ui` prints the initial admin password to the terminal and forwards the UI to
  `https://localhost:8443`.
- `make drill-drift` temporarily scales the API Deployment to one replica, records evidence under
  `docs/evidence/`, and waits up to 60 seconds for self-heal to restore two replicas.
